# WikiPulse / NexusAI — Technology Justification & Tradeoff Matrix

This document provides rigorous architectural justifications for every major technology used in NexusAI.

---

| Technology | Problem Solved | Alternatives Considered | Why Selected | Tradeoff Accepted | Evidence in Repo | When to Reconsider |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Apache Kafka 3.7** | Decouples bursty ingestion ($200\text{ ev/s}$) from slow downstream workers. | RabbitMQ, Redis Streams | Append-only disk commit logs, partition total ordering, consumer group horizontal scaling, event replayability. | Operational complexity of managing Kafka partitions and brokers. | `docker-compose.yml`, multi-worker consumer tests. | Workload requires lightweight pub/sub with sub-10k ev/day where Redis Streams suffices. |
| **`confluent-kafka` (librdkafka)** | Python Kafka client performance and socket stability. | `aiokafka`, `kafka-python` | Native C memory buffering (`linger.ms: 5`), low GIL contention, enterprise protocol parity. | Requires thread-isolated polling (`asyncio.to_thread`) for async workers. | `backend/app/kafka/consumer.py`, `producer.py`. | Pure-async Python runtime required without C extension support. |
| **PostgreSQL 16** | Canonical system of record for relational metadata and ACID guarantees. | MongoDB, Cassandra | Relational integrity, ACID transactions, foreign keys, unique constraint idempotency. | Single-node write vertical scaling limits. | `backend/app/models/`, `alembic/`. | Write throughput exceeds 50,000 writes/sec requiring distributed sharding. |
| **`pgvector`** | Vector embedding storage and ANN search co-located with relational data. | Pinecone, Qdrant, Milvus | Eliminates dual-write sync lag; enables single-query relational + vector SQL joins. | Bounded by single-node host RAM for HNSW graph residency (~32GB for 10M chunks). | `backend/app/search/vector.py`, 11.10ms measured benchmark. | Vector dataset exceeds 50M+ vectors requiring distributed vector sharding. |
| **PostgreSQL FTS** | Exact keyword, proper noun, and acronym retrieval. | Elasticsearch, OpenSearch | Zero external cluster overhead; GIN index integrates directly inside PostgreSQL SQL queries. | Basic BM25 ranking without advanced distributed cluster sharding. | `backend/app/search/keyword.py`, 1.93ms measured benchmark. | Document corpus exceeds 500M+ documents requiring cluster-wide full-text indexing. |
| **Redis 7** | Sliding-window velocity counters and distributed rate limiting. | SQL rolling window queries | Sub-millisecond $O(\log N + M)$ ZSET pruning (`ZREMRANGEBYSCORE`), zero DB table lock contention. | Volatile in-memory state; requires degradation handling. | `backend/app/redis/counters.py`, 0.5ms measured latency. | Analytics require complex multi-dimensional OLAP slicing (ClickHouse). |
| **FastAPI** | Control Plane REST endpoints, SSE broadcasting, and OpenAPI docs. | Django, Flask, Express | Native asyncio support, automatic OpenAPI docs, high-concurrency async I/O. | Single-threaded Python event loop requires strict off-loop thread delegation. | `backend/app/main.py`, `backend/app/api/v1/`. | Microservices rewritten in Go/Rust for ultra-low latency sub-millisecond API proxying. |
| **Reciprocal Rank Fusion (RRF)** | Merging disparate vector similarity and lexical term scores. | Score averaging, Min-Max normalization | Scale-invariant rank fusion ($k=60$); robust against score distribution skews. | Discards absolute score magnitude differences between adjacent ranks. | `backend/app/search/hybrid.py`, 15.89ms measured hybrid search. | Cross-encoder reranker inference latency becomes fast enough (<5ms) for all raw candidates. |
| **LLM Gateway** | Multi-provider AI summarization and resilient fallback. | Direct single-provider SDK (google-genai) | High availability; cascading fallback (Gemini $\to$ Ollama $\to$ Mock); zero vendor lock-in. | Fallback models produce varying depths of contextual synthesis. | `backend/app/llm/gateway.py`, fallback tests passing. | Enterprise commits exclusively to single dedicated cloud LLM endpoint. |
| **Server-Sent Events (SSE)** | Real-time live dashboard update streaming. | WebSockets, Polling | Unidirectional HTTP/2 streaming, native browser auto-reconnects, firewall friendly. | In-process bounded queue fanout does not scale across multiple API pods without Redis Pub/Sub. | `backend/app/api/v1/stream.py`. | Bidirectional interactive client-to-server messaging required (WebSockets). |
